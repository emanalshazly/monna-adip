# المرجع العربي لإطار MONNA ADIP

الإصدار: 0.2.0
الحالة: Research Extension 01

هذا مرجع عربي مصاحب. يظل [المرجع الإنجليزي](FRAMEWORK.md) هو المواصفة التقنية
الأساسية عند وجود اختلاف في الصياغة.

## 1. النطاق

يفحص MONNA ADIP قدرة وكيل الذكاء الاصطناعي على الحفاظ على سلامة البيانات
وسلسلة مصدرها أثناء اتخاذ القرارات وتنفيذ الأفعال. يركز على حد الثقة الموجود
**داخل بيانات الوكيل نفسها**، حيث قد تجتمع قيم موثوقة وغير موثوقة داخل تمثيل
واحد يراه النموذج.

يشمل الإطار:

- وكلاء الويب والبريد والبرمجة وRAG وMCP؛
- JSON وXML وMarkdown وDOM والتنسيقات المخصصة؛
- المعرّفات، والمصادر، والعناوين، ونتائج التحقق، وسجل الأدوات؛
- أفعال القراءة والكتابة والنقر والتنفيذ والدمج والإرسال والموافقة.

لا يدّعي الإطار:

- إثبات الحصانة ضد ADI أو Indirect Prompt Injection؛
- استبدال parsing أو authorization أو sandboxing الحتمي؛
- إنشاء exploit payloads أو تشغيلها؛
- تقييم ثغرات البنية التحتية خارج مسار بيانات الوكيل.

## 2. نموذج الثقة

| القيمة | التفسير |
|---|---|
| `trusted` | القيمة صادرة عن agent أو tool أو backend مخوّل، مع حماية سلامة يمكن التحقق منها. |
| `untrusted` | يستطيع طرف خارجي التحكم فيها أو التأثير فيها. |
| `derived` | قيمة مشتقة من مدخلات أخرى؛ ترث أقل مستوى ثقة مرتبط ما لم تتحقق بصورة مستقلة. |
| `unknown` | لا يمكن إثبات المصدر أو السلامة. تعامل كغير موثوقة في القرارات الحساسة. |

الثقة خاصية للمصدر والتحقق، وليست خاصية لاسم الحقل.

## 3. مستويات الفحص

1. **Block**: استدعاء أداة مع استجابتها أو وحدة من سجل التنفيذ.
2. **Object**: رسالة أو عنصر DOM أو Issue أو Transaction أو Document.
3. **Field**: خاصية مثل `sender` أو `url` أو `resource_id`.
4. **Value**: القيمة نفسها ومصدرها والتحويلات وأدلة التحقق.

يُفحص كل Action بصورة مستقلة، وتُربط مدخلاته بالحقول التي أنتجتها.

## 4. الضوابط السبعة

### C1 — رسم مصادر الثقة

لكل كائن وحقل، وثّق:

- المكوّن المنتج؛
- المصدر الأصلي؛
- مسار تأثير المهاجم؛
- التحويلات؛
- آلية حماية السلامة؛
- درجة الثقة ودليلها.

**البوابة:** لا يجوز بقاء حقل أمني في حالة `unknown` قبل تفعيل فعل عالي الأثر.

### C2 — تصنيف الثقة على مستوى الحقول

صنّف المفاتيح والقيم بصورة مستقلة، وحدد الدور الأمني:

```text
content | identifier | origin | authorization
tool_history | verification_result | action_argument
```

**البوابة:** لا تتحول بيانات غير موثوقة إلى metadata موثوقة لمجرد أن النموذج
فسّرها كهيكل منظم.

### C3 — اكتشاف تصادم حدود الثقة

سجّل الحالات التي يستقبل فيها النموذج تمثيلًا واحدًا يحتوي قيمًا موثوقة وغير
موثوقة، وحدد serializer وعائلة delimiters المستخدمة.

**البوابة:** يحتاج كل mixed-trust object إلى قرار موثّق بشأن العزل أو الوسم أو
randomization أو التحقق الحتمي.

### C4 — مراجعة الالتباس البنيوي

اسأل:

- هل يرى النموذج serialized data خامًا؟
- هل يجمع التمثيل بين structure ونص حر؟
- هل يستطيع النص الخارجي تقليد أسماء الأدوات أو إشارات المصدر؟
- هل تحمي عملية escaping الـparser بينما يبقى تفسير النموذج ملتبسًا؟

**البوابة:** لا تعتمد الأفعال عالية الأثر على تفسير النموذج وحده لحدود النص
والهيكل.

### C5 — تتبع اعتماد القرار

اربط كل Action Parameter بالحقل الذي أنتجه، مع تسجيل التحويلات. يجب أن تحتفظ
القيم المشتقة بسلسلة مصدر المدخلات.

**البوابة:** لا يعتبر الفعل مضبوطًا إن لم نستطع تحديد البيانات التي سببت الفعل
ومصدرها.

### C6 — بوابة سلامة الأفعال

للأفعال `high` و`critical` استخدم مجموعة مناسبة من:

- schema/type validation حتمي؛
- تحقق مستقل من المصدر؛
- server-side lookup باستخدام معرّف موثوق؛
- authorization policy دقيقة؛
- data-flow أو taint tracking؛
- sandbox restriction؛
- تحقق بشري من قناة مستقلة للحالات الاستثنائية.

الموافقة البشرية المبنية على نفس سياق الوكيل المحتمل فساده ليست تحققًا مستقلًا.

### C7 — ربط الحماية بأدلة التحقق

لا يكفي التصريح بوجود mitigation. يجب تسجيل:

- الضابط؛
- النطاق؛
- المالك؛
- هل يمنع أم يقلل أم يكتشف أم يساعد في التعافي؛
- حالة التحقق؛
- دليل اختبار أو Log أو Policy Reference أو Independent Review.

إذا كانت الحماية معلنة بلا دليل قابل للمراجعة، يصدر المحلل ADIP-07.

## 5. تصنيف النتائج

| المعرّف | المعنى | الشدة الأساسية |
|---|---|---|
| ADIP-01 | مصدر أمني مجهول أو بنية Inventory غير مكتملة | High |
| ADIP-02 | قيمة غير موثوقة أُسند إليها دور أمني موثوق | Critical |
| ADIP-03 | فعل حساس يعتمد على حقل غير متحقق منه | High/Critical |
| ADIP-04 | التباس بنيوي داخل كائن يجمع درجات ثقة مختلفة | Medium/High |
| ADIP-05 | الموافقة تعتمد على نفس السياق المحتمل فساده | High |
| ADIP-06 | قيمة مشتقة فقدت سلسلة مصدرها | High |
| ADIP-07 | إجراء حماية معلن بلا دليل تحقق | Medium |

لا تتضمن النسخة المفتوحة معادلة MONNA التجارية للأوزان أو حساب المخاطر.

## 6. الحد الأدنى من الأدلة

- Inventory للكائنات والحقول؛
- مبرر درجات الثقة؛
- ربط Action Parameters بمصادرها؛
- وصف التنسيق والـserializer؛
- مالك كل ضابط؛
- دليل تحقق أو تصريح واضح بفجوة الدليل.

## 7. حدود التفسير

MONNA ADIP أداة triage معماري. النتيجة النظيفة لا تثبت أن النموذج أو النظام
محصّن. يجب مراجعة implementation الفعلي، والسياسات، والصلاحيات، واختبارات
التكامل، وسلوك النظام عند الفشل.
