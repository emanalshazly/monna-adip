# البداية السريعة بالعربية

## 1. التثبيت

يتطلب المشروع Python 3.11 أو أحدث.

```bash
python -m pip install -e .
```

إذا أردت فحص الملفات وفق JSON Schema قبل التحليل:

```bash
python -m pip install -e ".[validation]"
```

## 2. إنشاء Inventory

انسخ القالب:

```text
templates/assessment.json
```

ثم وثّق:

- النظام وما يستطيع الوكيل تغييره؛
- كل data object يقرؤه الوكيل؛
- مصدر كل field؛
- درجة الثقة؛
- الأفعال ومدخلاتها ومسار التحقق منها؛
- المخرجات والأنظمة أو النماذج التي تستهلكها؛
- سياق التهديد والمراجع الخارجية الاختيارية؛
- إجراءات الحماية وأدلة اختبارها.

## 3. درجات الثقة

| القيمة داخل JSON | المعنى العربي |
|---|---|
| `trusted` | موثوق: صادر عن مكوّن مخوّل مع حماية سلامة يمكن إثباتها. |
| `untrusted` | غير موثوق: يستطيع طرف خارجي التأثير فيه مباشرة أو بصورة غير مباشرة. |
| `derived` | مشتق: ناتج من بيانات أخرى ويجب أن يحتفظ بسلسلة مصدرها. |
| `unknown` | مجهول: لا يمكن إثبات المصدر أو سلامته؛ يعامل كغير موثوق عند القرارات الحساسة. |

اسم الحقل لا يثبت الثقة. وجود اسم مثل `sender` أو `tool_result` لا يعني أن
القيمة موثوقة ما لم يوجد مصدر وضابط تحقق.

## 4. تشغيل التحليل

### تقرير Text

```bash
monna-adip inventory.json --format text
```

### تحقق Schema ثم تحليل

```bash
monna-adip inventory.json --validate --format text
```

### عدة ملفات

```bash
monna-adip agent-one.json agent-two.json --format markdown
```

### مجلد كامل

```bash
monna-adip inventories/ --recursive --format markdown --output report.md
```

### SARIF

```bash
monna-adip inventories/ --recursive --format sarif --output adip.sarif
```

## 5. صيغ النتائج

| الصيغة | الاستخدام الأنسب |
|---|---|
| `json` | التكاملات والـpipelines والمعالجة البرمجية. |
| `text` | المراجعة السريعة داخل Terminal. |
| `markdown` | تقارير PR والمراجعات البشرية. |
| `sarif` | GitHub Code Scanning وأدوات تحليل الأمان. |

## 6. رموز الخروج

| الرمز | المعنى |
|---:|---|
| `0` | التحليل اكتمل والحالة الإجمالية `REVIEW_READY`. |
| `2` | التحليل اكتمل ووجد `EXPOSED` أو `INCOMPLETE`. |
| `3` | خطأ في الملف أو JSON أو Schema أو القراءة أو الكتابة. |

رمز الخروج `2` ليس عطلًا في البرنامج؛ بل يعني أن الفحص وجد فجوات تتطلب
مراجعة.

## 7. فهم الحالة

- `INCOMPLETE`: معلومات المصدر أو الاعتماد المطلوبة ناقصة.
- `EXPOSED`: يوجد مسار High/Critical بلا ضابط مستقل كافٍ.
- `REVIEW_READY`: لا توجد فجوة baseline عالية أو حرجة؛ ما زالت المراجعة
  المتخصصة مطلوبة.

لا تمثل أي حالة شهادة أمان أو ضمانًا ضد الهجوم.
